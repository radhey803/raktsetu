Technical Architecture & Methodology

Medallion Lakehouse Architecture

A production-grade ELT pipeline designed with DuckDB and dbt Core as an Academic Project.

Bronze Layer

Immutable Landing & Ingestion

Asynchronous scraper querying eRaktKosh district endpoints with polite concurrency (Semaphore 10), identifiable academic User-Agent, and circuit breakers. Each scrape writes an immutable timestamped Parquet snapshot verified with SHA-256 before append-only loading into DuckDB raw tables.

  • Zero CSV round-trip corruption
  • Immutable timestamped landing files
  • Pipeline run tracking with row-count metrics
Silver Layer

Unnesting & Strict Normalization

dbt staging models unnest nested component structures into atomic rows per (facility, component, blood_group, units). Utilizes a strict SQL normalizer macro guaranteeing clinical distinction between B+ vs AB+ and O+ vs Bombay Oh+.

  • 35 dbt contract & data quality tests
  • Pure relational schema: one row per component group
  • Strict Rh factor and Bombay phenotype taxonomy
Gold Layer

Dimensional Marts & Analytics

Dimensional and aggregate marts powering sub-millisecond analytical queries. Replaces fragile application-layer regex parsing with pure SQL aggregations on fct_stock_current and incremental fct_stock_snapshot.

  • Reliability scoring algorithm (0–100 scale)
  • Append-only snapshots with zero fake data
  • Atomic blue/green serving database swap

Facility Reliability Scoring Algorithm

Every facility receives a computed trustworthiness score between 0 and 100 based on three objective criteria:

Data Freshness (50 pts) Updated ≤24h (50 pts) • ≤7d (30 pts) • ≤30d (10 pts)
Contact Validity (25 pts) Verifiable 10-digit mobile, landline, or active registry phone
Inventory Completeness (25 pts) Comprehensive component reporting across all 8 standard blood groups

Algorithmic Transparency

Blood Bank Trust Score (0–100)

Objective composite index measuring reporting reliability and contact readiness.

In an emergency, listing units that were updated weeks ago or listing invalid phone numbers creates life-threatening delays. Our Lakehouse computes a 0–100 Trust Score in dbt model mart_reliability_score using three objective pillars:

1. Data Freshness (50 pts maximum) Rewards active digital reporting to eRaktKosh:
<24 hours: 50 pts
<3 days: 35 pts
<7 days: 20 pts
<14 days: 8 pts
≥14 days: 0 pts
2. Contact Validity (25 pts maximum) Verified telephone contact exists in national registry:
Valid phone (≥8 numeric digits): 25 pts
Missing or placeholder phone: 0 pts
3. Component Completeness (25 pts maximum) Breadth of blood components managed and reported:
≥3 distinct components: 25 pts
1–2 components: 15 pts
0 components reported: 0 pts
